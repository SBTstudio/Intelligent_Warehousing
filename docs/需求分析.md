## 一、项目目标

传统仓储系统只做被动的出入库登记，与收银数据脱节，导致：

- 畅销品备货不足，错过销售；
- 滞销品长期压货，占用资金、逼近保质期；
- 店主凭经验订货，缺少数据依据。

本项目把**收银小票**和**库存数据**打通，在**端侧**完成统计、关联挖掘、
补货预测和本地大模型解读，做到：

1. 实时统计销售与库存，给出不同 SKU 的补货周期、补货量建议；
2. 从购物篮中挖掘商品连带关系，辅助货架陈列；
3. 分析销售趋势与季节规律，给出换季备货建议；
4. 不把经营数据上传云端，保护商业机密。

**非目标**：不自动生成采购订单，不替代店主决策；不做多终端分布式部署。

## 三、一般性规定

### 3.1 数据输入（2.2.1）

- 支持 CSV / TXT；
- 自动识别 `utf-8-sig` / `utf-8` / `gbk`；
- 校验 SKU 非空、数量为非负整数、日期可解析；
- 错误信息必须带行号；
- **原始文件只读，永不修改**；
- 非法行拒绝进入分析流程。

**实现**：`ingest.validate_receipt()` / `validate_inventory()` / `validate_products()`。
校验结果同时包含 `rows`（合格行）、`errors`（错误）、`warnings`（提示），
界面只在 `ok=True` 时允许导入。

### 3.2 输出与展示（2.2.2）

- 结果以**图表 + 文字**展示；
- 报告必须标注：计算时间、数据样本量、"本结果仅为经营辅助建议"；
- 不自动生成采购订单。

**实现**：报告页页脚统一追加时间、样本量、免责声明；图表页包含折线图、
柱状图、lift 热力图。

### 3.3 模型调用（2.2.3）

- 默认只调用本地 Ollama，不连接云端；
- v1.0.2 增加**显式可选**的第三方 OpenAI 兼容 API（DeepSeek / 通义 / OpenAI 等），
  默认关闭，需用户在参数配置里手动切换；
- 第三方只接收聚合摘要，不上传原始 CSV / 数据库 / 逐笔明细；
- 数据不足时提示"数据样本较少，建议补充更多销售数据"；
- 数字由算法层计算，LLM 只做文字解读。

**实现**：`app/llm/client.py` 统一封装 Ollama `/api/chat` 与 OpenAI
`/chat/completions`；`replenish` 在有效天数 < 7 时写入 `note` 提示；
所有 Prompt 都有"不要自行计算数字"的约束。

### 3.4 异常处理（2.2.4）

| 异常 | 行为 |
|---|---|
| Ollama 未启动 | 报告页显示"基础统计模式"，其余功能正常 |
| 第三方 API 401/403 | 提示鉴权失败，检查 Key / 模型权限 |
| 第三方 API 429 | 提示限流，检查配额 |
| 第三方 API 404 | 提示 Base URL / 模型名不存在 |
| 模型未下载 | 提示执行 `ollama pull qwen3:4b`，自动降级 |
| 推理超时（>60 s） | 终止本次调用，返回模板报告 |
| 模型返回非法 JSON | 自动重试 1 次；仍失败则降级 |
| 文件编码错误 | 提示尝试过的编码，不崩溃 |
| 数据库为空 | 分析页给出"请先导入数据"的引导 |

## 四、性能需求

| 编号 | 要求 | 实测 | 结论 |
|---|---|---|---|
| P-01 | 一周数据，购物篮/库存统计 ≤3 s | 示例数据 0.05 s 内 | ✅ |
| P-02 | 一年数据，完整分析 ≤15 s | 三年全量 0.25 s 查询 | ✅ |
| P-03 | 外部热点接口超时 8 s | 热点映射支持按超时降级 | ✅ |
| P-04 | 关联度、补货系数保留 3 位小数 | 表格按 3 位展示，计算保留全精度 | ✅ |
| P-05 | 销售/库存保留 2 位小数 | 金额/库存按 2 位展示 | ✅ |
| P-06 | 支持至少 2 年数据，总量 <2 GB | 3 年 77 万行 / 59.7 MB | ✅ |
| P-07 | 支持历史报告回看与备份 | reports 表 + `VACUUM INTO` | ✅ |

## 五、数据管理（2.5）

四类核心数据 + 一张配置表：

| 表 | 内容 | 保留策略 |
|---|---|---|
| `products` | SKU 档案（名称、品类、成本、售价） | 全量 |
| `transactions` | 交易头（订单号、时间、金额） | 全量 ≥3 年 |
| `transaction_items` | 交易明细（订单、SKU、数量、单价） | 全量 ≥3 年 |
| `inventory` | 库存快照（SKU、日期、数量、成本） | 全量；可降为按周 |
| `reports` | 分析报告（类型、时间、正文、参数） | 按需清理 |
| `config` | 业务参数 | 全量 |

- 幂等导入：`(order_id, sku_id)` 唯一索引 + `INSERT OR REPLACE`；
- 时间统一 ISO 文本，便于范围查询；
- `ANALYZE` 维护统计信息；
- 单文件数据库，`VACUUM INTO` 备份。
