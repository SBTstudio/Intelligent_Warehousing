# 5 分钟演示脚本

> 适用：课程验收 / 答辩现场
> 目标：在 5 分钟内展示"数据导入 → 算法 → 图表 → LLM 报告 → 降级"完整闭环

---

## 0. 演示前准备（30 秒）

```bash
# 确认环境
python tools/check_env.py

# 启动（Windows 双击 run.bat）
python main.py
```

- 如果数据库是空的，点「数据导入」→「一键载入示例数据」；
- 如果现场无法联网 / 不想等模型，**不要安装/启动 Ollama**，直接演示降级；
- 如果想演示真实模型，提前 `ollama pull qwen3:4b` 并保持 Ollama 运行。

---

## 1. 数据导入（40 秒）

1. 打开「数据导入」页；
2. 指向 `data/sample/receipts.csv`，说明：
   - 4,295 条明细、1,579 张小票、30 个 SKU、120 天；
   - 系统自动识别编码、列名；
   - 原始文件只读。
3. 打开 `data/sample/receipts_dirty.csv`，展示 4 处错误：
   - 空 SKU；
   - 负数量；
   - 小数数量；
   - "昨天下午"这种非法日期。
4. 强调：错误带行号，非法文件被拒绝，不会污染分析结果。

> 如果时间紧，直接点「一键载入示例数据」跳过文件选择。

---

## 2. 购物篮分析（60 秒）

1. 打开「购物篮分析」，最小支持度保持 `0.010`；
2. 点「开始分析」；
3. 指出：
   - 14 条规则，全部 lift > 1；
   - 最强规则：海飞丝洗发水 → 护发素，lift = 11.396；
   - 啤酒 → 花生米、可乐 → 薯片、面包 → 牛奶等 7 组埋入关系都被挖出；
4. 向下滚动展示 lift 热力图；
5. 解释 `lift > 1` 的含义：买了 A 的人比普通人更可能买 B。

---

## 3. 库存与补货（70 秒）

1. 打开「库存与补货」，点「计算补货与分类」；
2. 「补货建议」页签：
   - 红色行 = 已低于补货点；
   - 指出切片面包库存 0、可口可乐库存 2；
   - 说明 SS / ROP / 建议补货日的公式。
3. 切到「畅销 / 滞销」：
   - ABC 看销售额贡献，XYZ 看需求稳定性；
   - 解释为什么单看销量不够。
4. 切到「图表」：
   - 左侧切换 SKU 看日销量折线；
   - 右侧看销售额 TOP10 柱状图。

---

## 4. 分析报告（70 秒）

1. 打开「分析报告」，类型选「经营周报」；
2. 点「生成报告」；
3. 分两种情况讲：

**A. 已安装模型**：
- 状态显示"生成完成 · 本地模型"；
- 报告包含经营概况、补货、滞销、陈列四部分；
- 强调：数字全部来自算法层，模型只负责文字。

**B. 未安装模型（推荐现场演示）**：
- 状态显示"生成完成 · 基础统计模式"；
- 顶部琥珀色横幅；
- 正文仍有完整统计结论；
- 说明需求 2.2.4 的降级要求：模型挂了，库存/补货/分类仍可用。

4. 点「保存到历史」，再从底部下拉回看，展示 M10。

---

## 5. 参数与备份（40 秒）

1. 打开「参数配置」；
2. 把服务水平从 0.950 改成 0.990，保存；
3. 回「库存与补货」重算，指出安全库存变大；
4. 点「备份数据库」，生成 `backup_*.db`。

---

## 6. 性能与收尾（30 秒）

```bash
pytest -q
# 53 passed

python tools/benchmark_scale.py
# 77 万行 / 59.7 MB / 最慢 248 ms
```

收尾话术：

> 这个项目把"统计计算"和"语言表达"拆开了：
> 算法层保证数字可复现，LLM 层负责把数字讲成人话。
> 模型不可用时自动降级，核心经营功能不受影响。
