# 用户手册

> 适用版本：v1.0.3
> 适用对象：新零售店主 / 店铺运营人员 / 课程验收老师
> 阅读时间：约 10 分钟

## 零、直接使用安装包（推荐给店主 / 验收演示）

不需要安装 Python：

| 平台 | 安装包 | 使用方式 |
|---|---|---|
| Windows 10/11 x64 | `SmartWMS-Windows-x64.exe` | 双击运行 |
| macOS Apple Silicon | `SmartWMS-macOS-arm64.dmg` | 打开后拖进 Applications |

下载地址：[GitHub Releases](https://github.com/SBTstudio/Intelligent_Warehousing/releases/latest)

### Windows

1. 双击 `SmartWMS-Windows-x64.exe`；
2. SmartScreen 提示"未知发布者"时，点「更多信息」→「仍要运行」；
3. 数据自动保存在 `%LOCALAPPDATA%\SmartWMS\app.db`；
4. 首次打开到「数据导入」页点「一键载入示例数据」。

### macOS

1. 双击 dmg，把 `SmartWMS` 拖进 `Applications`；
2. 首次打开若提示"无法验证开发者"，右键 App →「打开」；
   或执行：

```bash
xattr -dr com.apple.quarantine /Applications/SmartWMS.app
open /Applications/SmartWMS.app
```

3. 数据保存在 `~/Library/Application Support/SmartWMS/app.db`；
4. 当前 dmg 为 Apple Silicon（arm64）；Intel Mac 请按下面的源码方式运行。

> 安装包内已带 120 天示例数据，但仍然需要手动点一次「一键载入示例数据」。
> Ollama 仍是可选项，不装时报告页会自动降级。

## 一、安装与启动

### 1.1 环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10/11（推荐）；macOS 13+ / Linux 也可运行 |
| Python | 3.10 及以上，推荐 3.12 |
| 内存 | 8 GB 可跑统计功能；16 GB 推荐跑本地 4B 模型 |
| 磁盘 | 约 3 GB（依赖 + 模型 + 数据） |
| 可选 | Ollama + qwen3:4b（不安装也能用，报告会降级） |

### 1.2 Windows 一键安装

1. 安装 Python 3.12（安装时勾选 **Add python.exe to PATH**）；
2. 双击项目根目录的 **`安装环境.bat`**：
   - 自动创建 `.venv`；
   - 用清华镜像安装依赖；
   - 运行 `tools/check_env.py` 自检；
3. 双击 **`run.bat`** 启动。

> 如果自检提示 Ollama 未安装，不影响统计功能；需要智能报告时再安装。

### 1.3 macOS / Linux

```bash
cd Intelligent_Warehousing
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python tools/check_env.py
./run.sh
```

也可以直接：

```bash
.venv/bin/python main.py
```

### 1.4 安装本地大模型（可选）

1. 到 [ollama.com](https://ollama.com) 下载并安装 Ollama；
2. 打开终端执行：

```bash
ollama pull qwen3:4b
ollama list
```

3. 保持 Ollama 在后台运行，重新打开软件即可看到状态栏显示"本地模型：在线"。

> 内存 8 GB 建议用 `qwen3:1.7b` 或 `qwen3:0.6b`；
> 内存 16 GB 以上可用 `qwen3:8b`。在「参数配置」页切换档位即可。

### 1.5 接入第三方 API（可选）

如果不想在本机跑模型，或希望用更强的模型，可以接第三方 OpenAI 兼容 API：

1. 打开「参数配置」；
2. 模型来源选择 **第三方 OpenAI 兼容 API**；
3. 填写 Base URL、模型名、API Key；
4. 点「测试连接」，成功后再点「保存配置」。

常见配置：

| 服务商 | Base URL | 模型名 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问（兼容模式） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| Moonshot | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |

**隐私说明**：第三方 API 只接收算法层聚合后的统计摘要（SKU 数、销售额、补货行、
关联规则等），不会上传原始 CSV、数据库文件或逐笔交易明细。
API Key 默认保存在本机 SQLite；公用电脑建议改用环境变量：

```bash
# macOS / Linux
export SMARTWMS_API_KEY="sk-..."
# Windows PowerShell
$env:SMARTWMS_API_KEY="sk-..."
```

## 二、第一次使用

### 2.1 载入示例数据

打开软件 → 左侧「数据导入」→ 点击右上角 **「一键载入示例数据」**。

系统会导入：

- 30 个 SKU 的商品档案；
- 120 天、4,295 条销售明细（1,579 张小票）；
- 30 条库存快照。

导入成功后，底部状态栏会显示数据库行数，其他页面即可分析。

### 2.2 推荐体验顺序

1. **购物篮分析** → 点「开始分析」→ 看规则表和热力图；
2. **库存与补货** → 点「计算补货与分类」→ 看补货表和畅销/滞销；
3. **图表** → 切换 SKU，看日销量折线图；
4. **分析报告** → 选「经营周报」→ 点「生成报告」；
5. **参数配置** → 改补货周期/服务水平 → 保存 → 回补货页重算。

## 三、页面说明

### 3.1 数据导入

支持三种文件：

| 类型 | 必需字段 | 可选字段 |
|---|---|---|
| 购物小票 | `sku_id`、`qty`、`date` | `order_id`、`unit_price` |
| 库存 | `sku_id`、`stock_qty` | `sku_name`、`cost`、`snapshot_date` |
| 商品档案 | `sku_id` | `sku_name`、`category`、`cost`、`price` |

模板下载：

- 点「下载小票模板」「下载库存模板」「下载商品档案模板」，会保存中文表头的空白 CSV；
- 模板带 UTF-8 BOM，Excel 双击打开不乱码；
- 填好后回到本页选择文件导入。

操作：

1. 点「选择小票文件」「选择库存文件」或「选择商品档案」；
2. 系统自动识别编码（UTF-8 / GBK）和列名同义词；
3. 校验结果显示：
   - 绿色「校验通过」：可以点「确认导入」；
   - 红色「校验未通过」：列出具体行号和原因，禁止导入；
4. 导入完成后，其他页面会自动收到"数据已更新"提示。

**原始文件只读**：系统不会修改你选择的 CSV/TXT，只把合格数据写入
`data/app.db`。

常见错误示例：

```
第 17 行：qty 为 -2，必须是非负整数
第 23 行：date 为 昨天下午，无法解析为日期（示例：2026-01-01 10:00）
第 31 行：sku_id 为空
```

### 3.2 购物篮分析

- **最小支持度**：默认 0.010。数值越小，挖出的组合越多，但噪声也越多；
- **只看正向连带**：勾选后只保留 `lift > 1` 的规则（需求要求）；
- 表格列：SKU A / 商品 A / SKU B / 商品 B / 支持度 / 置信度 / 提升度 / 关联强度；
- 下方热力图：横纵轴是商品，颜色越深表示 lift 越高；
- 悬浮在表格上可看到完整数字；lift ≥ 3 标为"强连带"。

**怎么用**：把 lift 最高的几组商品摆在相邻货架或同一端架；lift < 1 的组合
说明可能互相替代，不要放在一起。

### 3.3 库存与补货

**补货建议**页签：

| 列 | 含义 |
|---|---|
| 日均销量 | 指数平滑后的 d̄ |
| 需求波动 | 日销量标准差 σ |
| 安全库存 | z·σ·√LT |
| 补货点 | d̄·LT + SS，库存低于它就该下单 |
| 剩余天数 | (库存 − SS) / d̄，负数表示已经低于安全库存 |
| 建议补货日 | 今天 + 剩余天数 − LT |
| 建议补货量 | 覆盖 LT + 一个补货周期 + 安全库存 |

红色行 = 需要补货；「状态」列显示"需补货 / 正常"。

**畅销 / 滞销**页签：

- ABC：销售额贡献（A 核心 / B 中坚 / C 长尾）；
- XYZ：需求稳定性（X 平稳 / Y 波动 / Z 极不稳定）；
- 判定：畅销（绿）/ 正常 / 滞销（橙）/ 呆滞（红）。

> 示例数据的日销量波动较大，因此多数 SKU 的 XYZ 为 Z，
> 这是真实零售数据的常见现象；重点看 ABC 与周转天数。

**图表**页签：

- 左侧：下拉选择 SKU，查看 120 天日销量折线；
- 右侧：销售额 TOP10 柱状图，按判定着色。

### 3.4 分析报告

报告类型：

1. **经营周报**：补货、畅销、滞销、关联陈列的综合解读；
2. **滞销归因**：对滞销/呆滞商品给出原因与处理动作；
3. **陈列建议**：基于 lift > 1 的规则给出货架方案；
4. **换季推荐**：根据季节指数、同比、环比推荐备货方向；
5. **热点映射**：粘贴热点文本，映射到店内品类。

操作：

- 选择类型 → 点「生成报告」；
- 模型可用时显示"生成完成 · 本地模型"或"生成完成 · 第三方 API"；
- 模型不可用时显示琥珀色横幅和"基础统计模式"，正文仍有完整统计结论；
- 「复制全文」复制到剪贴板；
- 「保存到历史」写入数据库，之后从底部「历史报告」下拉回看。

报告页脚固定包含：生成时间、样本量、SKU 数、"本结果仅为经营辅助建议"。

### 3.5 参数配置

| 参数 | 默认值 | 作用 |
|---|---|---|
| 补货周期 | 7 天 | 建议补货量覆盖的天数 |
| 到货提前期 LT | 3 天 | 供应商送货时间 |
| 服务水平 | 0.950 | 决定 z 值；越高安全库存越大 |
| 最小支持度 | 0.010 | Apriori 阈值 |
| 滞销阈值 | 45 天 | 周转天数超过它判滞销 |
| 模型来源 | Ollama 本地 | 本地 Ollama / 第三方 OpenAI 兼容 API |
| 本地模型档位 | qwen3:4b | Ollama 模型名称 |
| API Base URL | 空 | 第三方接口地址，例如 `https://api.deepseek.com/v1` |
| API 模型名 | deepseek-chat | 第三方模型名称 |
| API Key | 空 | 可保存本机，也可用 `SMARTWMS_API_KEY` 环境变量 |
| API 超时 | 60 秒 | 第三方接口请求超时 |

其他按钮：

- **恢复默认**：把控件恢复为默认值（还需点保存才会落库）；
- **刷新模型列表**：本地模式读取 Ollama 模型，第三方模式读取 API 的 `/models`；
- **测试连接**：用当前表单参数测试 API，不必先保存；
- **备份数据库**：选择路径，使用 `VACUUM INTO` 生成单文件备份；
- **打开数据目录**：在文件管理器中打开 `data/`。

保存后，补货页和报告页会提示"参数已更新，点击重新计算"。

### 3.6 实时库存 / 收银辅助

「实时库存」页让软件在营业过程中持续使用，而不是只做事后分析。

**新增 / 编辑商品**

填写：商品编号、商品名称、品类、进价、售价、库存，点「保存 / 更新商品」。

- 新编号：创建商品档案，并记一条"建档"流水；
- 已有编号：更新名称/品类/进价/售价；如果库存字段变化，会调整到填写的数值并记"调整"流水；
- 「载入选中商品」：把表格中选中的商品回填到表单，适合改价或盘点。

**卖出 / 补货**

- 「当前库存」表格每行有「卖出 1」「补货 1」：
  - 卖出：库存 -1，同时生成销售流水（订单号、单价、时间）和库存事件；
  - 补货：库存 +1，同时生成补货事件；
- 顶部「扫码 / 手输」支持输入 SKU、商品名或条码，选择来源（手动 / 条形码 / NFC），
  设置数量后点「卖出」或「补货」；
- 每次操作都会在「变动记录」页签留下精确到秒的时间戳、变动量、变动后库存、
  来源和订单号。

**条形码 / NFC 接入**

当前手动输入框已经走统一的 `realtime.record_sale_by_code()` 接口。
以后接条码枪或 NFC 读卡器时，在程序启动处注册一个解析器即可：

```python
from app.core import realtime

def resolve_barcode(code: str) -> str | None:
    return barcode_map.get(code)   # 返回 SKU 编号

realtime.register_code_resolver("barcode", resolve_barcode)
```

UI 和库存/销售逻辑不需要改。

> 实时卖出会同步写入 `transactions` / `transaction_items`，
> 因此购物篮分析、补货预测、分析报告会使用最新的营业数据。

## 四、数据格式与示例

### 4.1 购物小票 CSV

```csv
order_id,sku_id,qty,date,unit_price
T00001,S002,2,2026-06-16 20:58,4.00
T00001,S016,1,2026-06-16 20:58,11.90
```

- `qty` 必须是非负整数；
- `date` 支持 `2026-06-16`、`2026-06-16 20:58`、`2026/06/16` 等；
- 编码支持 UTF-8（带/不带 BOM）与 GBK；
- 列名支持中文同义词，如"商品编号""购买数量""交易时间"。

### 4.2 库存 CSV

```csv
sku_id,sku_name,stock_qty,cost
S001,青岛啤酒,6,3.20
```

`stock_qty ≥ 0`；`cost` 可选。

### 4.3 商品档案 CSV

```csv
sku_id,sku_name,category,cost,price
S001,青岛啤酒,饮料,3.20,5.50
```

## 六、常见问题

### Q1：启动时报"缺少 .venv"

先双击 `安装环境.bat`，或按 1.3 节手动创建虚拟环境。

### Q2：界面中文显示为方块

- Windows：系统需安装微软雅黑（默认自带）；
- macOS：需有苹方字体（默认自带）；
- Linux：安装 `fonts-noto-cjk`。

### Q3：报告页显示"基础统计模式"

本地模式说明 Ollama 未启动或模型未安装，按提示：

```bash
ollama list
ollama pull qwen3:4b
```

第三方模式说明 Base URL / 模型名 / API Key 或网络有问题，
到「参数配置」点「测试连接」查看具体原因。

统计功能不受影响，可以继续看补货表和图表。

### Q4：模型很慢 / 超时

- 关闭其他占内存程序；
- 换更小模型：`qwen3:1.7b` 或 `qwen3:0.6b`；
- 在「参数配置」里把模型档位改成已安装的模型；
- 报告页默认最多等待 60 秒（第三方 API 可在参数配置里调大），超时会自动降级。

### Q5：导入 CSV 报"无法识别编码"

用 Excel 另存为「CSV UTF-8」；或确认文件不是加密/二进制格式。
系统会依次尝试 `utf-8-sig`、`utf-8`、`gbk`。

### Q6：导入时报"缺少必需列"

检查表头。支持的同义词包括：

- `sku_id`：SKU、商品编号、商品编码、货号；
- `qty`：数量、购买数量、销量；
- `date`：交易时间、日期、销售时间；
- `stock_qty`：库存、现有库存、库存数量。

### Q7：为什么我的商品全被判为 Z 类？

Z 类是"日销量波动大"，不是"卖得差"。零售日粒度数据本身波动就大；
可结合 ABC 与周转天数一起看。如果希望更平滑，可导入更长时间的数据，
或后续版本支持按周聚合判断。

### Q8：数据会不会上传？

不会。所有数据保存在本机，LLM 只访问 `127.0.0.1:11434`。

## 七、卸载

1. 关闭软件；
2. 删除项目目录（含 `.venv`、`data/app.db`）；
3. 如安装了 Ollama，可在系统设置中卸载，模型文件位于用户目录的 `.ollama`。

> 卸载前请先备份 `data/app.db`。
