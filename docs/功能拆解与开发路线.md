### 为什么是 PySide6 而不是 Tkinter

- PySide6 有 **Qt Designer**，可以拖拽画界面，不用手写布局代码
- 表格控件 `QTableWidget` 能直接显示补货建议表、滞销清单
- 图表通过 matplotlib 嵌入，折线图 / 柱状图 / 关联热力图都支持
- 能打包成 `.exe`，交付时是一个真正的软件安装包

Tkinter 虽然 Python 自带、零安装，但界面观感老旧，做复杂表格和布局极其痛苦。

### 关于已装的工具

- **IntelliJ IDEA 这个项目用不到** —— 那是 Java 的 IDE
- **Python 3.14 那个目录是坏安装**（只有 Doc 和 Lib，没有 python.exe），别用它
- 统一使用 `C:\Users\<用户名>\AppData\Local\Programs\Python\Python312\python.exe`

```bash
python -m pip install PySide6 pandas numpy matplotlib requests
```

1. 到 ollama.com 下载 Windows 安装包，一路下一步
2. 安装完成后打开 PowerShell，执行：

```bash
ollama pull qwen3:4b
```

内存 16G 以上可以拉 `qwen3:8b`（质量更好但更慢）。**先拉 4b 跑通，别一上来就拉大的。**

3. 验证服务在跑：

```bash
ollama list
```

### 3. 验证程序能跑

双击项目根目录的 `run.bat`，应该弹出一个窗口。看到窗口就说明环境通了。

## 六、你要手搓的核心算法（公式备查）

### M3 — Apriori 关联规则

```
支持度  support(A→B) = |同时含 A 和 B 的交易数| / 总交易数
置信度  confidence(A→B) = support(A∪B) / support(A)
提升度  lift(A→B) = confidence(A→B) / support(B) = P(A∩B) / (P(A)·P(B))
```

- `support` 太低（< 0.01）说明组合出现太少，是噪声，先剪枝
- `support ≥ 最小支持度` 的项集叫**频繁项集**，Apriori 的核心就是逐层扩展频繁项集
- **`lift > 1` 才是正向连带**：说明买了 A 的人比普通人更可能买 B；`lift = 1` 表示 A、B 相互独立；`lift < 1` 表示负相关

### M4 — 补货预测

```
日均销量 d̄    ：用指数平滑或 Holt 线性趋势求得
需求波动 σ_d ：同一时间窗口内日销量的标准差
安全库存 SS  = z × σ_d × √LT          （服务水平 95% 取 z = 1.65）
补货点 ROP   = d̄ × LT + SS            （LT = 供应商到货提前期，天数）
建议补货日   = 今天 + (现有库存 − SS) / d̄ − LT
```

### M5 — ABC × XYZ 分类

```
ABC（按销售额）：累计占比 ≤70% 为 A 类，≤90% 为 B 类，其余为 C 类
XYZ（按需求稳定性）：变异系数 CV = σ / μ
     CV < 0.2        → X 类（需求平稳）
     0.2 ≤ CV < 0.5  → Y 类（需求有波动）
     CV ≥ 0.5        → Z 类（需求极不稳定）
滞销判定：C 类 且 Z 类 且 周转天数 > 阈值
```

这套交叉分类比单纯拍一个销量阈值专业得多，答辩时是亮点。

## 七、开发纪律（三条硬规矩）

1. **算法层不许 import 界面层。** `app/core/` 里绝对不能出现 `from PySide6 import ...`。这样算法可以脱离界面单独测试，也让"这部分是我自己写的"这件事无可辩驳。
2. **数字全部由算法层产出，LLM 一个数字都不能算。** 本地 7B 模型算数不可靠，而文档要求保留 2 位 / 3 位小数，两者冲突。LLM 只接收聚合后的摘要做文字解读。
3. **原始数据只读。** `data/raw/` 里用户导入的文件永远不修改，符合文档 2.2.1 的要求。
